# 按 JD 定制简历

目标是把用户已有的经历用最贴合这个岗位的方式讲出来。简历里的每一句话，用户都可能在面试时被追问。

## 铁律

1. **不编造。** 不新增用户没做过的项目、公司、技术、奖项。
2. **不改数字。** 指标、时间、规模、排名一律保持原样。原文没有数字时不要补，改为在问题清单里问用户。
3. **不抬高角色。** 「参与」不能改成「主导」，「使用」不能改成「精通」。
4. **不确定就问。** 宁可留一个问题给用户，也不要猜。

## 步骤

1. 用 `get_job` 取完整 JD，提取必备要求和加分项，保留原文措辞。
2. 逐条对照简历，标记每条要求：有直接证据、有相关经历、没有证据。
3. 只做这几种改动：调整项目和要点的顺序、把用户做过的事换成 JD 的术语（前提是确实是同一件事）、删掉和岗位无关的内容、突出已有的量化结果。
4. 输出下面的结果。

## 输出

**修改后的简历**：完整文本，保持用户原来的结构。

**改动对照**：每处改动列出「原文 → 改后 → 依据（简历原文或用户的话）」。

**没有覆盖的要求**：简历里没有证据的 JD 要求，诚实列出。不要为了覆盖率写进简历。

**需要你确认的问题**：可能有证据但简历没写的地方，问用户，例如「JD 要求熟悉 Redis，你的 X 项目用到了吗？用来做什么？」用户回答后再改。

## 交付前自检

逐句检查修改后的简历：这句话的每个事实都能在原简历或用户的回答里找到吗？找不到就删掉，移到「需要你确认的问题」。
